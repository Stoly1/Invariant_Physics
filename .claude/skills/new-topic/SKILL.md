# Новая тема в справочник

Пользователь — репетитор. После занятия он присылает теорию и источник задач,
из которых нужно собрать страницу темы. Общий контекст проекта — в `CLAUDE.md`,
прочти его, если ещё не читал.

## 1. Разбери, что прислано

Нужны две вещи:

- **теория** — текстом, фотографией конспекта или ссылкой;
- **источник задач** — ссылка на сборник, фото страницы или список задач.

Чего не хватает — спроси сразу, одним вопросом, и не начинай без этого.
Особенно без задач: выдумывать их нельзя.

Уточни тему и раздел, если по материалам неочевидно. Загляни в `темы/`,
чтобы понять, в какой раздел тема ложится и какой ставить `порядок`
(темы внутри раздела идут по возрастанию, шаг 10 — чтобы можно было
вставлять между).

## 2. Собери задачи

Из присланного источника. Если это ссылка — открой её (WebFetch).
Если фото — читай прямо с него.

У **каждой** задачи должен быть ответ из источника. Задачу без ответа
не включай — либо найди ответ, либо выброси задачу.

Не придумывай условия и не пересчитывай ответы «в уме»: расхождение
всплывёт, когда ученик сдаст решение.

Разумный объём — 10–15 задач, разбитых на 2–3 части по подтемам
(`### Часть 1. …`). Внутри части — от простого к сложному.

## 3. Напиши теорию

Определения бери из присланного, по смыслу дословно, и **сохраняй
обозначения пользователя** (путь `L`, перемещение `\vec{S}` — см. `CLAUDE.md`).
Расхождение с тетрадью ученика недопустимо.

Сверх присланного добавь:

- **типовые ошибки темы** — то, на чём ученики валятся;
- **проверку на здравый смысл** — как самому заметить, что ответ неверный;
- **«Где это встречается в жизни»** — 2–4 бытовых примера (навигатор,
  шагомер, камеры на трассе). Пользователь просил это отдельно;
- **рисунок в SVG**, если он объясняет лучше слов.

Структура: термин → определение → пример → типичная ошибка.
Обращение на «ты», коротко, без восклицаний и воды.

## 4. Создай файл

`темы/<раздел>/<название>.md` по образцу `шаблон-темы.md`.
Готовые примеры для ориентира — в `темы/кинематика/`.

## 5. Собери и проверь

```bash
python3 скрипты/собрать.py
```

Затем проверь программно:

- тема появилась в списке, число задач совпадает с ожидаемым;
- в `docs/t/**/*.html` не осталось `\frac`, `\vec`, `$$`, `&lt;svg` —
  это значит, что формула или рисунок не отрендерились;
- баланс тегов (`html.parser`), все `src` указывают на существующие файлы;
- у каждой задачи есть ответ.

Скриншот снять нельзя — нет разрешения на запись экрана, `screencapture`
отдаёт обои. Не трать на это попытки, попроси пользователя взглянуть самому.

## 6. Отчитайся

Коротко: что за тема, сколько задач, что добавил от себя, что нарисовал.
Отдельно назови всё, в чём не уверен: спорные ответы, места, где источник
расходится с присланной теорией, задачи, которые пришлось выбросить.

## 7. Публикация — только по просьбе

`git push` выкладывает материал в открытый доступ. Сам не публикуй.
Предложи и дождись ответа:

```bash
git add -A && git commit -m "Тема: <название>" && git push
```
